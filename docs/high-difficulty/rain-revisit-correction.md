# 交岸回访：成功顺序不等于必要顺序

2026-09-28。依据作者本次自述、会话 `40954ed4-f9f2-4067-b764-3e2db01b7624` 路线和真实引擎回放。

## 作者反馈

作者认为本次可能仍混有此前提示的记忆。较明确的经验是直觉路线失败后愿意尝试反直觉安排，但尚未化为稳定具体技巧。不能把本次无演示操作当作首次独立发现。

本次交岸记录为 221 次有效移动、6 次 blocked、9 次重开、45 次撤销。最后一个 blocked 发生在胜利后，不作为困惑证据。

## 修正此前分析

此前观察到作者先完成横条，随后撤销，将小块完成后再收尾横条。由此推测前导缺少“何时才能收尾”的教学，证据不足。

路线第 234 条记录（局内步数 26）为：玩家 (3,3)，横条 (3,4)，小块 (2,2)。真实引擎回放 `上、左、下、左、下、右、右、右` 可直接获胜；独立求解器也返回 solved。无需撤回横条，不是延迟收尾的必要性实例。

因此不得据此生产“横条必须等小块完成后才到底”的教学题。原盘面和命题不变。新增回归测试只锁定这个已观察局面的可解性，不改引擎或求解器。

## 更具体的观察

该局面的小块本身就能在向下滑行时把玩家停在 (2,1)，让玩家经左侧绕到推侧。缺少的未必是另造障碍，而可能是辨认当前物件已提供的停点。

这只是当前设计诊断假设，不宣称作者完全不懂该规则。后续路线把小块再次向左移动，不能因此断言作者有意识否定了上述路线。

## 下一步边界

暂停连续扩写前导；回汀、择汀、隔汀仍保留原状态。隔汀有本关内明确用途理解的自述，交岸迁移仍未独立验证。

下一候选如制作，应研究“从所需推侧倒查可用停点，包括待推动物本身”，而非泛泛的反向操作或未经证明的收尾顺序。必须验证关键站位、合法接近路线及反事实，不能只检测选定解的推动先后。

对于路线中每个被称为死局、必须撤销或失去条件的状态，先通过真实规则回放/求解核验。未测试只能写“玩家未继续找到路线”；预算耗尽仍是未知。
