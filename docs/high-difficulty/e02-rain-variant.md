# E02 × Rain：同底板变式设计卡

日期：2026-09-04。**仅策划，未制作关卡、未求解全图、未进入任何目录。** 本卡回答旧技巧在已经核验的 Rain 机制下有没有新的因果用途，不预占正式名额或标为 D7。

## 亲缘关系与前置

- 父题：`lab-e02-shared-bay`／指纹 `f225f6fe`，见[E02 本版](e02-prototype.md)。
- 先学普通推动、完整占格和 Rain 的滑行／邻接操作；还应理解 E02 的暂存与取回关系。未学会规则的困难不计高难。
- 预定保留：左上出入口、上横／右竖两簇 Goal、横竖两物件、下侧浅停带及底部绕行排。让玩家从盘面辨认熟悉关系，不用标题“旧关升级”提示答案。
- 可见变化先只考虑晴／雨；若后续需要更换几格几何，明确记录改变的是何种停止条件，不冒称只切一个天气就保证新解。
- 旧技巧仍有效：放得下不等于可取回。新增研究问题：连着一条走廊，也不等于玩家能在需要的推侧停下。

## 已核对的规则事实

[真实 move()](../../src/engine/game-engine.ts) 先检查邻接操作，再计算雨中落点；[引擎测试](../../src/engine/game-engine.test.ts)已覆盖“空旷处滑到阻挡前、邻接 Block 只推一格”。本轮不更改这条规则。

从 E02 初态临时用真实规则验证 `→↑→`：晴天角色到 `(2,0)`，雨天到 `(3,0)`，因 `(4,0)` 为墙而停止。下一次右输入的效果自然不同。此局部探针未落盘为新关，**它只证明同一方向串不能原样照抄，不证明策略已经升级**。

新机制材料沿用项目的[推／穿与停点核查](../../research/13-pushability-design-audit.md)及上述测试，不追加未经核验的外部作者方法论。

## 要检验的设计假设

唯一总命题候选：**一个有用的暂存位置，必须同时保留物件的取回方向和玩家可抵达的停止条件；借出其中一个条件后，要在后续任务前重新制造它。**

不是增加第三个临时箱来顺次做独立刹车题。先研究现有横物是否能在两个阶段承担不同停止边界：

1. 起初的浅停既让竖物通过，也允许角色在某个中间推侧停下。
2. 为运输竖物而横移浅停物，会取消这个停止边界；原来“走回那里”的计划失效。
3. 通过可恢复的中间布置重新取得停止条件，再取回横物。移动哪个物件做刹车必须改变另一个物件的可取回性，才算必要组合。

上述三段是未证实假设，不是当前地图的解法。若单纯切雨后仍可按 E02 相同宏推动序列解题，只多按几次走路键，归类为巩固复用，不冠以进阶或高难。

## 自然第一计划与预期反证

玩家可能认出下侧暂存带并尝试旧方法：“横物在那里停好，之后随时绕回去取。”反证应该是可见的停止物位置、边界和当前行进方向；不得靠相机遮挡或不知道的雨规则让人卡住。

保留的不是方向序列，而是“每次借位都要准备取回条件”的原则。没有认出旧题的玩家，也必须能用已学 Rain 规则从当前图独立推出问题；熟悉感只能帮助提取，不是必需记忆钥匙。

## 后续地图阶段的失败用例

1. 先用真实 `move()` 核对旧准备状态在雨中缺的是哪一个可达停止点，而非只比较坐标串。
2. 求解整个候选并回放；禁止“为后续取回重新制造停止条件”的语义关系后应无解。若工具尚不能完整表达该关系，标为未知，不用 `rain-slid` 出现一次冒充证明。
3. 解耦对照给予独立停止边界，保留所有任务与暂存关系；应解除重新制造停止条件的需要。
4. 再把天气改回晴：检查恢复的是哪个旧能力。晴／雨各自可解，不代表已经具有所宣称的继承关系。
5. 审计替代入射方向、永久停车、目标区域替代刹车、两物件换顺序，以及仅重新路由行走即可绕过的方案。
6. 如需要辅助停止物，先证明它不可被两件现有物品或边界替代；不能为了保住 Rain 题材硬加无关任务。

## 取证与淘汰

只在纯空间实验已经取得足够反馈后考虑制作；本卡不提前放行跨机制高难地图的批量生产。

- 测试先被动记录是否认出 E02 结构。结束后再问哪些原则仍可用、哪个条件变了，避免事先告诉玩家要对照旧关。
- 若只认出外形而无法说明因果联系，检查底板锚点；若完全照抄旧计划即可过关，只算巩固，不算进阶。
- 若必须隐藏停止状态、引入未学规则，或唯一收益是增加行走长度，则淘汰／重构。
- 若单纯切雨就无解，先找真实原因，不能更改 Rain 规则保住同底板。
- 评级、人数与放行依[统一协议](../playtest-protocol.md#technique-transfer-evidence)。本卡暂无目标难度数字、陌生样本或成功率。
