# 三代理试玩反馈 · 2026-09-03

## 不含解法的结论

三位 AI 测试者均实际完成了同样的 19 关：9 个基础热身关，以及目前新增的 31–36、57–60。共收集 57 次通关观察，不是 57 个不同关卡，也不是三名真人样本。

本轮支持两个不同的判断：**技巧迁移确实发生了，但高难度目标尚没有得到证实。** 绝大多数目标关被评为认知难度 2–4；少数较高评分还混有新规则学习、目标遮挡和物体分组不清的影响。不能据此把任何关卡升级为“实测 D8”，也不能反向宣称所有真人都会觉得简单。

三位共同报告的主要问题是：目标被玩家或物体盖住、相邻白色物体的归属不清、墙与地面初见时难分，以及竖长棋盘需要反复滚动。它们是信息表达和执行负担，不能用来补足逻辑难度。

关卡盘面、规则、难度元数据和验收状态均保持原样。本轮只恢复本地服务、提供隔离的玩家版测试入口并收集反馈。当前课程仍是 70 个可玩条目、120 个规划位置，不代表 120 关已经完成。

三者使用同一模型、相互独立的上下文与页面，没有设计背景或解法提示。正常玩家能看到的关名、目标与操作说明没有被屏蔽；按钮定位时的额外可访问名称暴露已在协议中逐项披露。结论只适用于这轮工具辅助 AI 试玩。

## 重复出现的表现问题

| 问题 | 实际观察 | 解释边界 / 建议 |
| --- | --- | --- |
| 目标被完全遮住 | A/B/C 在 31 都先移动才看到角色下面的 Goal；33/34/59/60 也有被白块遮挡的目标 | 不应把“先发现终点在哪里”误算为推侧难度。建议在覆盖时仍保留可读的目标轮廓或状态标记，不改格子色彩语义 |
| 一件多格物 vs 多件相邻物不清 | 三者均在 03/05 对比或 35/60 起始盘面提到分组；移动后才确认归属 | 应通过每件物体的轮廓与内部连接表达分组，保持实际占格不变；不以缩小物体制造空气间隙 |
| 墙与地面初见难分 | 02 三者均因误读暗色区域发出无效方向输入；C 在 60 又出现类似判断 | 优先加强静态边界/纹理层级，避免增加与 Rain 冲突的第二套格色规则 |
| 竖长棋盘超出视口 | 三者均指出 57 无法同时看全上下结构与方向按钮 | 协调者另外实测：1265×720 视口中棋盘约 672×1075 CSS px。建议按可用宽高共同缩放并保持控件可达；该测量不是第四个试玩样本 |

多位代理遇到整页截图窄列、滚动后短暂黑块而后恢复。普通视口截图恢复正常，缺少证据将这些现象归因于游戏缺陷；单独保留为工具/绘制时序待查，不计入已确认问题。

### 技巧迁移成立，难度深化证据不足

- **32 → 33 → 34**：从腾出通路，到临时离开已完成位置，再到共用绕行线，三者都能陈述迁移关系。但 34 的解题过程与 33 很接近，没有明显增加需要排除的竞争方案。
- **36 → 57 → 59**：三者均把既有访问顺序应用于旋转或换形状后的盘面。作为迁移练习有效；作为 D6–7 难题，暂未表现出同级的新的推理要求。
- **58**：B/C 明确注意到不能机械套用此前的顺序口号，必须看具体绕行空间，这是正面的边界学习证据；但三者仍在行动前看出了主要过程。
- **60**：各物体逐次开放推侧的依赖更有趣。A/B 在一次分组探查后顺利完成，C 因隐藏目标和错误回推使用一次 Undo。应先排除可读性混淆，再验证剩余的依赖推理是否足够深。

“离开终点”“远处先完成”“把地图转过来”等标题被多位代理明确视为有效提示。本轮包含这些正常玩家可见文案，不能把成功归因于纯盘面教学。后续可比较中性标题的候选版本，但不能通过隐藏物体状态来人为制造困难。

### 第 35 关存在前置知识混杂

三者在本轮都首次接触 Rain。A 发现输入距离不同并进行两次撤销后调整策略，评分 5；B/C 各 4 步完成，评分 3，但明确表示没有充分验证 Rain 的完整邻接规则。

协调者只在汇总阶段对照了目录与源码：当前 35 号 P5 使用 Rain，而基础 Rain 停点组在显示 38–40 才出现。这不只是本轮短热身遗漏，还需要复核课程顺序；但自由选关下，其他玩家也可能提前学过 Rain，不能推断所有玩家都缺此前置知识。

建议下一轮将“理解 Rain 后的技巧应用”与“第一次学习 Rain”分开观察。本轮不改原始测试结果，也不补讲规则后将复测当作同一次盲测。

### 没有被本轮验证的内容

- 没有测试完整顺序课程、H1–H8 的长期避刺信念、70–75 的 Spike 反转或实验室三关。
- 没有系统验收 Spike 粒子、Gate 动画、键盘长按、所有视口与无障碍设置。方向按钮和用到的 Undo 正常，不能外推全部交互已验收。
- 没有真人样本、跨会话 D9–10 解题证据、专家难度校准或 P11/P12 的作者验收。
- 机器必要性/可解性证明、AI 通关记录与真人可理解性分别是三类证据，不能互相替代。

## 建议的后续顺序（未自动执行）

1. 保留本轮版本和原始记录，先完成作者自己的试玩反馈。
2. 用不改盘面/规则的表现调整解决目标、物体分组与竖屏布局问题；给这些问题补视觉/交互回归测试。
3. 复核 Rain 前置顺序与候选关标题。让 57–59 承担明确的迁移/巩固职责，不仅凭数量、方向变化或走路步数标成高难。
4. 在候选池深化 60 所体现的多物体依赖和相互制约，目标是增加必须推理的选择，而非搬运量；已验收基础关保持冻结。
5. 用信息条件明确的新测试者及真人盲测复核，再决定是否推进 P11/P12 与横向扩写。本轮不修改 `measured`、`confidence` 或发布门槛。

## 工程验证

- 玩家版入口复用同一 `App` 与引擎，隐藏作者分析，自由选关，使用标签页级 sessionStorage；正常游戏存档仍走原有存储。
- 新入口先补失败用例再实现；26 个测试文件、223 项测试和生产构建通过。
- 结束时正常入口与玩家版入口均返回 HTTP 200；关卡文件与规则引擎 SHA-256 与开测前一致。
- 本轮没有提交或推送；没有改动任何关卡盘面、规则、目标评级或玩家验收结论。
