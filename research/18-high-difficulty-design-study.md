# 高难关卡设计：Witness、SSR 的证据与 Oshi 的修订方向

研究与访问日期：2026-09-03。

本轮只做文献核查、代码对照和设计方法修订，不改盘面、规则、课程排序或运行时难度。Stephen Lavelle 的逐条来源核查见 [SSR 一手证据笔记](17-ssr-primary-source-evidence.md)。

## 1. 先给结论

我们此前把“技巧出现了”“解法必须使用技巧”“技巧比较难发现”混为一谈。前两项可以由地图与求解器证明，第三项不能。

作者实玩确认：当前样板 31–36、57–58 是 D3，59–60 是 D4；原先 D5–8 标签只是未达成的目标。不能用机器审计通过或 AI 评分覆盖这个结果。[作者反馈原始记录](../docs/playtests/2026-09-03-author-p1-p10.md)

这轮学习得到的工作方向是：

- 从 Witness 学习的不只是规则教学，还有**不同约束如何共同决定同一个答案**。
- 从 SSR 学习的不只是规则反转，还有**局部成功为什么未必是全局进展，以及有趣构想如何反复打磨成关卡**。
- 对高难 Oshi，优先研究**不能一次完成、互不相干地收尾的子任务**：物件、通路、推侧和 origin 在不同阶段互相借用，玩家必须先找到可恢复的中间状态。
- 上述都是设计方向，不是“照做即可得到 D10”的公式。现阶段应先找到作者确认为超过 D4 的少量样题。

## 2. Witness：不是简单地把两种符号放在一起

### 2.1 作者明确谈到预先设计交互

**一手事实。** Blow 在 2026 年直接访谈的第一问中回顾 Witness：单种谜题符号会预先考虑后期如何与其他符号发生有趣作用；初学时未必预见这些作用，理解后又会觉得自然。这段谈的是 Witness，不是用其新游戏宣传替代旧作证据。[Blow 直接访谈，2026-05-14](https://thenerdstash.com/we-spoke-to-order-of-the-sinking-star-creator-jonathan-blow-on-puzzles-and-narrative-fast-paced-vs-methodical-audiences-and-more/)

**我们的理解。** 真组合不是“左边做一次 A，右边做一次 B”，而是：满足 A 的一种选择，会改变 B 还有哪些合法选择；B 的要求又反过来限制 A。这可以只用已熟悉规则产生新的推理，不必让玩家猜新规则。

### 2.2 一个可以核对规则的具体例子

FUN 2018 论文的 Table 2 与 §5 定义：某区域有一颗某色星星时，该区域参与此计数的同色符号总数必须恰为两个；同色方块也参与。方块同时施加自己的颜色分区约束。[Witness 形式化论文，印刷页 3:4、3:8](https://erikdemaine.org/papers/Witness_FUN2018/paper.pdf)

下面是我们依该定义构造的局部示例，**不是声称复现了某一张原版关卡**；只考虑星星、方块，不引入消除符号等其他规则：

| 同一区域的黄色符号 | 星星的计数条件 |
| --- | --- |
| 两颗黄星 | 满足 |
| 一颗黄星、一枚黄方块 | 满足 |
| 两颗黄星、一枚黄方块 | 不满足：三个同色符号 |

关键不在多一种图案，而在“原本已经配对的星星，会因方块的位置而不再合法”。同一条分区线必须兼顾两类要求。

**Oshi 对应问题。** 某个 Goal 既是目标又能改变可走空间时，不能只让玩家先推一次 Goal、再推一次 Block；应寻找“为 Block 布置最终覆盖，会破坏玩家仍需使用的推侧；为了拿回推侧，又必须改变 Goal 状态”的共同约束。这里只确定研究关系，尚未证明某张候选地图实现了它。

### 2.3 先探索系统，再提炼表达

**一手事实。** Marc ten Bosch 官方页面对他与 Blow 在 IndieCade 2011 合讲的摘要，强调探索系统中的行为、后果和模式，再找到核心观念的清晰表达；还明确与传统的组合式设计作区分。本次读取的是作者摘要，未据此声称听完演讲。[官方演讲说明，2011-11-03](https://marctenbosch.com/news/2011/11/designing-to-reveal-the-nature-of-the-universe/)

**应用。** 不应从“还缺一个 D8 槽位”倒推一个带三种机制的盘面。应先在固定规则中发现值得研究的局面，再决定它适合教学、迁移还是高难。课程目录组织发现，不代替发现。

### 2.4 清晰不等于简单答案

**一手事实。** Modeling Epiphany 中，Blow 强调从初见者角度观察、削减无关心智噪音，同时明确没有普适设计规则。其 2013 官方文章认为，开放结构可以容纳困难而微妙的谜题，因为玩家可以先去别处；追求的也不是单纯刁难。[2014 直接访谈](https://www.gamedeveloper.com/design/-i-the-witness-i-modeling-epiphany)、[2013 官方文章](https://blog.playstation.com/2013/02/20/the-witness-an-open-world-puzzle-game-on-playstation-4/)

**应用。** 应让玩家看清 origin、完整占地形状、Gate 配对和出口占用，却不在标题中直接交代完成次序。允许离开难题，与保留真正困难的题目并不矛盾。看不清、猜碰撞和动画含糊仍然是缺陷，不是高难。

## 3. SSR：值得学习的创作过程与具体反例

**一手事实，精简复核。** Lavelle 在官方播客中否认“少机制、多后果”是最初既定原则；Jenga 塔构想长期打磨后才成为关卡。Clover 则围绕“烤熟后仍要能返回”的问题孵化。对应页面时间标签为 `00:06:49–00:10:44`、`00:11:18–00:12:12`。本次读的是自动转写，不是音频听辨；说话人归属与更多限制详见 [逐条核查](17-ssr-primary-source-evidence.md)。[Lavelle / Draknek & Friends 访谈](https://zencastr.com/z/AJ3PmvXZ)

### 3.1 学 Clover 的目标关系，不能照搬其胜利条件

**我们的推论。** 一个容易理解的局部目标，可以遮住完成全局所需的另一项资源。玩家要从“把这件事做完”转为“以仍能完成后续任务的方式做完”。这比多放一个障碍更有研究价值。

Oshi 在全部真实 Block 完成时即获胜，玩家不用站 Goal。因此不能直接移植“全箱完成后还得走回来”，也不能暗加新的通关条件。应把同样的张力放在最终胜利之前：例如某箱已完成，但另一箱仍需借用它占据的通路；或者先把箱子运进区域，却必须预留其最后一次推动的站位。[当前胜利判定](../src/engine/game-engine.ts)

### 3.2 不把意外困境包装成作者深意

**反证。** 玩家在官网报告 Canal 可以完成却阻断后续进度时，Lavelle 在 2018-02-05 的评论 #32 表达了否定态度。这与有意研究的关内次级目标不是一回事；本次没有复现该问题，也不判断当前版本是否仍然存在。[作者官网评论 #31–32](https://www.increpare.com/2016/04/stephens-sausage-roll/)

**应用。** Oshi 的难题允许关内可撤销的死局，不允许损坏总体进度。不能用“SSR 也很残酷”替软锁、规则歧义或大量重复操作辩护。

### 3.3 不把作者的规则探索许可误移植给 Oshi

Lavelle 在创作 SSR 时也曾选择和调整行为；这不意味着 Oshi 应为了难题改规则。我们的任务是在作者已裁定并核验的规则内寻找后果。没有找到严密地图的构想可留在实验室，不需要硬塞进正式序号。

## 4. 专业分析与人类难度研究补上了什么

### 4.1 一个关卡可以容纳一段完整的学习过程

**专业作者观点，不是 Blow / Lavelle 的自述。** Taiji 作者 Matthew VanDevander 在 2017 年文章及本人回复中，用建立、发展、高潮讨论谜题节奏；特别指出整个过程可以发生在单个谜题内部。他也提醒这不是普适公式，并在后续评论表示当时尚未打完 SSR，因此不把文章当成 SSR 全作权威解剖。[How Do We Pace Puzzle Games?，2017-07-12 及作者回复](https://taiji-game.com/2017/07/12/31-how-do-we-pace-puzzle-games/)

**应用。** 三关组仍可作为课程组织方式，但高难关不必限制为“一眼找到一个窍门，然后执行到底”。可以保持一个总命题，同时让玩家经历几个互相关联的中间发现。六推短尾应该从**最后一个确实需要理解的里程碑**计算；不能任意把倒数第六推动命名为顿悟来满足指标。

### 4.2 比状态空间更值得检查的是：子任务能否分开解决

**学术事实。** Jarušek 与 Pelánek 的 STAIRS 2010 研究比较 35 个均为四箱、尺寸相近的推箱子谜题，记录到 294 名至少解出一题的参与者、2,071 次成功解题。以下是 Table 2 中指标与成功解题时间中位数的 Spearman 相关系数：[作者托管论文，§2.2、§4.2、§5](https://www.fi.muni.cz/~xpelanek/publications/stairs2010-final.pdf)

| 指标 | 该样本中的秩相关 |
| --- | ---: |
| 状态空间大小 | -0.07 |
| 最短解长度 | 0.47 |
| 两组箱子的任务分解指标 | 0.82 |

论文的分解指标考察箱子分组后，完成解答最少需要多少次组间切换；取所有解的最低成本，不是只数作者指定路线。研究对象有限、线上参与不受完全控制，而且采用成功者用时；相关性既不是因果证明，也不能直接换算成 Oshi 的 D1–10。

**Oshi 推论。** 值得检查的不是“我加了三个箱子”，而是“玩家还能不能把它们看成三个独立小题，逐个彻底做完”。如果不行，是什么共享资源要求他先部分处理 A，再处理 B，之后重新调整 A？

这也不是让我们机械最大化箱子切换次数。无意义往返同样可以制造高数值。该指标只用于发现可疑的独立子题、比较候选的解耦版本；真正的人类思考仍要试玩观察。

### 4.3 区分三种不同东西

以下是我们的工作分类，不冒称为论文量表：

- **认知发现**：玩家重新理解某个一直存在的后果，例如物件回位可用于换侧。
- **推理规划**：玩家知道所有规则，但必须协调多个不能独立收尾的任务。
- **执行摩擦**：已经理解后还要走很远，或因画面、操作不清而出错。它不是前两项的替代品。

Witness / SSR 的形式复杂度论文研究的是可扩展问题族；不能因此证明某个小关有 D8 难度，更不能证明它好玩。本轮新增的人类难度论文比单纯复杂度结论更贴近当前问题，但仍只提供候选诊断依据。

## 5. 对当前 P 样板的有据对照

下表“代码事实”来自 [P 关卡定义](../src/levels/mastery/push-footprint-levels.ts) 中的总命题与有序事件；难度来自作者反馈。右栏是待通过解题过程验证的设计解释，不是伪造的玩家心理记录。

| 现有关卡 | 代码中实际研究的结构 | 作者评分 | 我们的解释 / 改进方向 |
| --- | --- | --- | --- |
| 57 / P7 | 将“远先近后”换到另一朝向 | D3 | 检查迁移有价值，但朝向变化没有自动增加规划层次。保留练习身份。 |
| 58 / P8 | A → B → C 顺次腾格 | D3 | 依赖链变长不等于难：若当前只有一个合理后继，就很容易顺着做。 |
| 59 / P9 | L 形的远端格使近目标封路，必须远先近后 | D4 | 更充分地要求读完整形状，但核心次序仍可以压缩成一个判断。 |
| 60 / P10 | 同一长物前进一步做任务一，再前进一步做任务二 | D4 | 已有重复使用，但仍是向前推进的序列；是否需要选择中间形态、借路后返还，尚未成为这种结构的要求。 |

这说明需要改变研究对象，而不是把 D8 改名为“更难的 D8”。尤其不能把“有四个里程碑”当作玩家完成了四层推理：事件发生次数不等于思考层数。

目前没有逐关用时、首个假设和分支选择记录，不能断言以上结构就是全部原因；但已足以否定原目标难度已实现的说法。

## 6. 把学习转成可检验的候选结构

以下不是已完成地图、不是解法证明，也不改动冻结关。它们是下一轮小规模实验的设计问题；若真实 `move()` 无法实现，舍弃布局而不是增加规则。

### A. 纯空间：借路必须还路

从现有“把 A 移开，完成 B，再移回 A”继续深入：

- A 的完整占地形状释放通路甲，却同时占去通路乙。
- B 必须先进入一个**可恢复的暂存状态**，不能立即完成；它随后需要经乙取得最终推侧。
- 再调整 A 可以开放乙，但必须先为 A 自己保留另一侧推位；C 若存在，只能承担这项真实约束，不能用来增加工作量。

应寻找的不是直观的 A、B、C 排序，而是一个能解除表面循环依赖的中间状态。若“先做 A 才能 B、先做 B 才能 A”实际上没有合法中间态，就是无解，不是高难。

反事实测试：多给一个独立绕行口之后，原先必要的暂存或回调是否消失？若消失而其他规则不变，就能定位难点来自共享通路，而非搬运距离。

### B. Gate：挡住出口不是附加任务，而是改变入口的操作身份

把出口占用、入口可推性和同一箱子的未来推侧联结起来：暂存箱堵出口，让入口能够作为物件移动；随后又必须收回暂存箱，恢复通道，并借新通道完成尚未解决的任务。

重点是这些准备能否共同成立，而非让玩家按唯一走廊依次“堵、推、通”各做一次。反事实版本可提供独立推侧，检查远端布置是否不再需要规划。不得把 Gate 传送、移动端点、方向保持写成另一套规则。

### C. Spike：把已学会的避险原则变成有限适用的策略

长期铺垫里，触刺可以真实地撤销物件的有用位置、破坏刚获得的通路；当前关的正解确实不需要它。玩家学到的应该是“这里碰刺会失去进展”，而不是假的“物件永久消失”。每个辅助 Spike 都必须影响原技巧的选择，否则只是装饰性威胁。

后期揭示时，只改变**回位的用途**：通常行走拿不到所需推侧，物件回 origin 却让玩家留在远端。熟练阶段再让 origin 同时承担暂存或站位用途，迫使玩家决定何时占用、何时腾空。

重置目标物件与角色死亡必须区分。当前角色死亡会复位全部状态，不能把“先完成任务，再让玩家死回去”设计成保留进度的技巧；物件回位才可用于这类局部状态操作。[独立 death reset 实现](../src/engine/game-engine.ts)

继续遵守既定 H 关审计：禁用物件 / 死亡重置后仍有同成本正解；允许重置不产生更短最优解；删除 Spike 会放宽有意义的约束。它们只能验证铺垫的结构，不能证明玩家真的产生了避刺信念；顺序盲测不可省略。

## 7. 修订后的生产与检验方法

下列是 Oshi 的建议工作流程，不冒称为两位作者的统一公式。本轮没有执行地图生产。

1. **先探索一个具体关系。** 记录真实规则下，某物件的哪种位置会同时改变两项条件；保留失败尝试。不要从关号和目标难度反推机制数量。
2. **写总命题和竞争方案。** 不只写正确路线，还写玩家为什么可能相信一个错误计划、盘面如何允许他自己反驳它。错误应来自策略假设，不来自隐藏规则。
3. **寻找必要的中间状态。** 高难候选至少要回答：为何不能逐件完成？哪个资源必须多次转交？何时完成会失去后续操作？不强迫每一关同时满足所有形式。
4. **保留 TDD 机器门槛。** 初态有解、回放符合真实引擎、必要条件不可绕过、近最优宏策略与变异审计都保留。状态预算耗尽只能记为未知，不能当成无解或高难证明。
5. **对比解耦版本。** 在实验副本里增加独立通路、取消一个共享条件或固定某个端点，比较核心策略是否坍缩。不要只测删了元素会不会无解；还要问它是否支持有意义的选择或可读性。
6. **盲测思考，不只记通关。** 候选试玩前只提供正常玩家信息；记录第一计划、第一次计划被否定、提出的新子目标、最后一次理解后的执行量。必要时解后访谈，避免边问边提示解法。
7. **先超过真实 D4 锚点。** 用 59、60 作为当前作者量表的比较对象，先测试少量 D5–6 候选；若仍只需一个直观次序判断，就保留为练习或退回实验室，不扩产假 D8–10。

NYU PRACTICE 2014 的 Blow 本人问答把试玩描述为核对自己的设想是否符合实际，而不是笼统征求方向。这支持“看是否真的发生预期理解”的用途，但不规定 Oshi 的样本数量。[NYU 官方问答，Jonathan Blow 部分](https://gamecenter.nyu.edu/events/practice/practice-2014-2/)

固定三关组、D1–10、盲测人数、最后顿悟后最多六推，都是 Oshi 已选择的生产或验收约束；本轮没有发现它们是 Blow / Lavelle 的普适法则。研究也不自动推翻用户已确定的课程结构，调整正式标准仍需作者确认。
