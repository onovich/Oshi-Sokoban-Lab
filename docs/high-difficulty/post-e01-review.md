# E01 之后：候选结构复审

状态：2026-09-04，筛选后制作的 E06 已与简化关一同获作者组验收：短庭 D4、旁路 D5、回环 D6。以下保留最初候选筛选的风险判断，不将它们改写成事后预测。

作者对 E01 的反馈是约 D3、不到一分钟、几乎无需改变计划。准确记录见[作者反馈](../playtests/2026-09-04-author-e01.md)。问题不在“暂存不必要”，而在一次看清局部阻挡后便能顺序执行。

## 五张任务书的风险

| 候选 | 容易再次退化成什么 | 继续制作前必须回答 |
| --- | --- | --- |
| E02 暂存交接 | 把“别推太深”换个位置重演 | 借出空间后，取回条件是否被另一任务改变，不能只靠浅停一次？ |
| E03 空 Goal 用途 | 最近目标堵路，所以换个目标 | 最终分配是否受中途交接反向约束，而不只排除一个坏 Goal？ |
| E04 延迟恢复 | 已完成物让路一次，再放回 | 第一阶段结束后，原先合理的恢复安排为什么不再适用？ |
| E05 两次借路 | 同一形状按固定顺序移动两次 | 去程的安排如何限制回程的接近方向，而非单纯第二次开门？ |
| E06 交错准备 | 三件物体的固定排序 | 是否所有逐件做到底的排列都失败，而可恢复准备能改变后续任务许可？ |

## 本轮选择

优先研究 E06 的三方交错准备，不按 E 编号机械生产。只使用普通推动、静态 Goal 和不可旋转物体；不加 Spike、Gate、Rain 等未知量。先以能否超出作者 D4 锚点作为待试玩问题，不因为任务书原写 D6 就认定本版本是 D6。

查找具体盘面时，搜索量、推动交替和回撤次数只用于定位待检查的例子。最终必须能用地图上实际存在的暂存、推侧与收尾条件解释，否则淘汰。不能把随机复杂地图、长搬运或一串强制动作当作结果。

机器合同分为两层：

1. 可回放解、所有逐件处理排列的反事实、真实状态关系的必要性以及有效解耦对照。
2. 检查合理误选与可恢复路线、物件和地板变异、最后预定理解点后的执行尾巴。自动事件不是人的顿悟时刻。

正式盘面、E01、稳定 ID 与进度不改。若找不到能解释资源冲突且通过反事实检查的候选，就保留研究结果，不拿更长的 E01 充数。具体人类放行仍由[统一协议](../playtest-protocol.md#high-difficulty-pilot)决定。

## 本轮落点

[E06 回环／旁路](e06-prototype.md)已进入开发实验室，制作时的原型目标是 D5，并未从任务书继承 D6。三方交接与 A 撤回完成两类禁令在主版穷尽无解，开一个返回站位后的对照均可绕过；删格后仍保持这一关系。作者初次均未解出后追加[短庭](e06-scaffold.md)，后来解开 08／07、观看 06 演示，并给出[08=D4、07=D5、06=D6 的组验收](../playtests/2026-09-04-author-e06.md#author-acceptance)。

本组可用，未来按简单到难安排。技巧可归纳性有限是进一步优化方向，不是撤销验收的理由。下一轮既可补清楚的前置关系，也可拓展另一种更可辨认的技巧；不再只通过增加交接次数追求高难。跨机制与相似底板的新增策划合同见[设计总纲](design-guide.md#technique-growth)。
