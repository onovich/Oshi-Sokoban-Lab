# BB2 借埠：移动 Goal 制造通行条件

稳定 ID `lab-bb2-goal-permission`；LAB 49；指纹 `60603a18`。目标 D5 是待测假设，不是实测评级。

## 核心与玩家条件

4×4 晴天，两只未完成单格 Block、一个静态 Goal、一个可移动 Goal。前置是普通推动及 Goal 能推则推、受阻可穿过。回埠的移动／回收练习可以在前，但不是要先完成所有空间或 Rain 题。

同一 Goal 先借墙面改变可进入性，再移到箱子旁借箱子阻挡穿过，取得另一侧站位，最后送到左箱下方。玩家选择的是 Goal 的中途用途，而不仅是终点位置。中间箱可以先完成；左箱暂时承担阻挡作用，不能只按离目标远近逐件搬运。

这不是“把挡箱移开，使 Goal 原位同方向重新可推”的题。探索时只记方向的宽泛谓词曾把换位置后的左推误当成原位许可恢复；加上位置有效期后发现可以绕过。生产版明确采用较窄的‘搬 Goal 利用阻挡取得通路’命题，不沿用错误证明。

## 机器证据

`node scripts/audit-bb2-goal-permission.mjs`；公共 `move()` 回放及 `solveLevel()`。

- 18 输入、6 推，路线 `LDRDUURLLUDRDLUULD`，初始两箱均未完成。
- 分别禁 Goal 推动、禁 Goal 穿过，穷尽无解。
- 自定义真实状态搜索：禁‘后方由 Block 阻挡的 Goal 穿过’，穷尽无解。不是仅检查演示路线。
- 两个局部对照：墙边上行、箱边左行，移去相应阻挡后，同一输入从穿过变推动。
- 解耦开放 (3,2) 右绕行格后，不必借箱子阻挡穿过。开放 (2,0) **不能**解除该关系，已否定原先的上绕行假设。
- 六个初始空闲地面格逐个封墙均无解；删去了初稿右侧与左下无必要空地。

这不是全部宏策略唯一性的证明，也不证明玩家最后顿悟发生在哪一步。数字难度、教学迁移与执行尾巴仍需试玩。
