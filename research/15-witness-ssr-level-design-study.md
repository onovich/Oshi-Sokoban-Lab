# 《The Witness》与《Stephen’s Sausage Roll》关卡设计研究

研究日期：2026-09-03  
用途：为 Oshi 基础课程与 120 关 `mastery-v2` 课程提供可追溯的设计依据，而不是为既定关卡寻找事后背书。

## 1. 证据边界

本项目按以下优先级处理规则与设计判断：

1. Oshi 作者在本项目中的当前裁定。
2. Oshi 原版 Unity 代码、Shader、资源和行为对照测试。
3. 作者本人撰写的文章、演讲或直接访谈。
4. 同行分析与学术研究。
5. 商店评价和玩家讨论；它们只能提示体验风险，不能证明作者意图。

文中使用三个标签：

- **事实**：来源直接支持的陈述。
- **推论**：从事实推导出的设计解释，来源本身未如此表述。
- **应用**：Oshi 决定采用的生产约束。

Jonathan Blow 明确说过，设计实践没有一套普适规则。因此本文不宣称存在可机械套用的“Blow / Lavelle 公式”；这里只提取有来源支持、且能被 Oshi 测试或盲测验证的工作假设。

## 3. 三种课程动作

本项目采用的综合模型是：

> 《The Witness》让玩家建立规则，Understand 式对照帮助玩家划定规则边界，SSR 式推演迫使玩家发现该规则尚未显露的后果。

这里的 Understand 只是对“最小对照”结构的便捷称呼。本轮没有找到足够强的一手作者材料，所以不把它写成作者方法论，也不让它承担课程的主要证据。

### 3.1 建立（establish）

- 地图是最小正例，但必须有目标、选择和失败可能，不能是按一次键的动画展示。
- 新规则的关键输入很容易触发；触发后最多 3 次有效交互完成。
- 视觉只强调因果变量，不显示内部命题或答案。

### 3.2 定界（boundary）

- 相对建立关只改变一个被命名的 `contrastVariable`。
- 地图击破最可能出现的过度概括，例如“锚点能移动，所以多格物就能移动”。
- 对照状态必须有测试；不能偷偷同时更换几何、身份和远端条件。

### 3.3 推演（inference）

- 初看存在一个可静态观察的“不可能”结构。
- 常规方案应很快被盘面否定，避免玩家在巨大搜索树中盲试。
- 解法依赖一阶公理的二阶后果，例如“物体回 origin”进一步意味着“玩家被留在另一侧”。
- 新假设一旦形成，应能解释整张地图；不能靠隐藏例外。
- 顿悟后有效推动不超过 6 次。

## 4. Oshi 的公理—后果图

| 机制 | 一阶事实 | 二阶后果 | 可进入组合关的三阶后果 |
| --- | --- | --- | --- |
| 基础推动 | 玩家只能从物体背后推一格。 | 箱子位置会创造或销毁未来推侧；完成顺序就是访问权分配。 | 与 Fake 或目标分配结合时，非任务物也能成为支点。 |
| Footprint | 多格实体的全部组成格共同移动、共同判定。 | 主动移动形状会腾出远端格；远端组成格也会先碰机关。 | 与 Spike 结合时，任一组成格可遥控整件实体回位。 |
| Number / Goal | 完整覆盖与身份兼容同时决定完成。 | “几何上能放”与“任务上正确”是两个约束集合。 | 与 Fake 结合时，数字相同仍不能改变任务身份。 |
| Fake | 参与碰撞和推动，不参与胜利。 | 可充当临时墙、停止器、站位资源。 | 与编号目标结合时可控制稀缺目标的访问而不能替代真 Block。 |
| Spike | 物件触刺尝试回 origin；玩家触刺走独立 death reset。 | 回位是一条远程返回边，且推动者仍留在触发侧；origin 占用控制该边是否可用。 | 与 Gate 结合可让远端拓扑复位；与 footprint 结合可让远端组成格触发。 |
| Movable Goal | 可放置时被推；受阻时可穿过。 | Goal 同时是终点、物体与条件式地形。 | 在 Rain 中既可编程停止点又是最终目标。 |
| Rain | 无邻接动作时沿输入方向滑到阻挡前。 | 其它物件的位置可以编程停止点；邻接动作会切换输入尺度。 | 滑行把方向带入 Gate，远端阻挡又可把传送切换成推门。 |
| Gate | 出口落点开放则保持方向穿越；受阻才尝试推入口。 | 眼前行为由远端格决定；移动端点重写可达拓扑而不解除配对。 | 与 Spike 组合可形成可重置的动态网络。 |

## 5. 生产门槛

一个关卡进入正式课程前必须同时满足：

1. **规则一致**：Unity 对照测试与作者裁定均通过。
2. **命题明确**：`LevelTheorem` 只有一个 proposition，且不显示给玩家。
3. **可解**：求解器找到解并回放成功。
4. **必要**：禁止每个 `requiredPredicate` 后都无解。
5. **紧凑**：关键实体删除/封墙变异能说明它是证明元素、可读性边框或应被删除的冗余。
6. **短尾**：建立关关键事件后不超过 3 次有效交互；推演关关键事件后不超过 6 次有效推动。
7. **可理解**：至少三次盲测；推演关至少五次且至少 3/5 无提示发现目标后果。

自动化只能完成前六项中的机器可判部分。盲测数据缺失时，关卡状态必须写作“候选”，不能写成“已验证正式关”。

## 6. 明确不采用的做法

- 不把更大的地图、更多箱子或更长搬运直接等同于推演。
- 不用文案提前说出内部命题；界面只给胜利目标、操作和进度。
- 不为单关制造规则例外，也不因关卡需要修改已经核验的原版规则。
- 不把求解器的高搜索量或计算复杂度当作品质指标。
- 不让 Path Spike 承担当前主课程；它的动态状态不利于静态推测。
- 不让某个高难推演关成为全部课程的单点阻塞。

## 7. 与实现的对应关系

- `src/levels/course-catalog.ts`：21 个三关组、公理、命题、前置组和分支。
- `src/levels/authored-course.ts`：63 个候选关卡的纯数据盘面。
- `src/levels/level-analyzer.ts`：可解性、最短移动/推动、命题绕过和顿悟尾巴分析。
- `src/levels/course-progress.ts`：定界关掌握标记、分支解锁和“下一关”路由。
- `src/engine/types.ts` 与 `src/engine/game-engine.ts`：机制领域事件；逻辑状态不依赖动画或课程文案。
- `docs/playtest-protocol.md`：真人盲测记录协议；只有填写记录后才算完成第七项门槛。
