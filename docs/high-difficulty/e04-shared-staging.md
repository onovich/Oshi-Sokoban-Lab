## 可执行计划与冲突

- **B 优先**：只推动 B 一次就能完成它，其他物件尚未移动；但会切断 A 所需的后续操作路径，局面无解。它继承父题的约束，不宣称全新技巧。
- **C 优先**：先向下、再向左两次可以完成 C，其他物件尚未移动；但其目标占用 A 所需的推侧。值得注意，真正的不可逆承诺发生在第一次左移到 `(2,4)`，尚未进入 Goal 时，而不是最后的完成反馈。退回两步可回到仍有解的暂存状态。
- **可行关系**：先移动 C 以便准备其他物件，再让 A 上移，之后继续操作 C。C 的具体暂存路线可以不同；不能把作者某条固定方向序列当作唯一策略。

机器只能证明上述方案可执行及其后果。它们是否会吸引玩家、是否引发计划修正，仍须由第一计划的实际反馈确认。

## TDD 与反事实

沿用 `createGame()`、`move()`、原空间 oracle、领域事件和实际 App 操作，不增加规则特例。

1. 完整求解与回放至胜利：当前 BFS 见证为 60 步／15 次推动。推动数是该见证的统计，不当作人类难度或全局最少推动的证据。
2. 禁止在 C 完成前操作其他物件，穷尽无解。
3. 必要事件关系为“C 推动 → A 从 `(1,2)` 上移 → C 再推动”；禁止该关系后无解。最初指定 C 的具体暂存格和最终入 Goal 方向，发现合法替代路线后已撤销过强断言，保留共同因果关系。
4. B／C 两条优先完成路线实际回放，确认只有所选物件移动、确实完成，但全局仍未胜利，随后穷尽无解。Undo 和 Restart 能恢复对应先前状态。
5. 只开放墙格 `(0,2)`，保持物体、Goal 及 C 优先路线不变，并禁止箱子利用新增格：同一 C 优先局面恢复可解，C 可一直保持完成。这表明冲突来自玩家操作侧，而非“C 一定要最后完成”的额外规则。
6. 20 项物件／Goal 删除与初始空格封墙变异通过，无未标注冗余或未知项。实体删除的事件引用失效并非独立耦合证据，需结合上述状态反事实和单格解耦检查理解。
7. UI 测试选择 LAB 17，实际操作完整见证至胜利，检查正式进度不变。通用演示求解测试自动覆盖目录新增关。
