# Oshi 课程盲测协议

自动求解器可以证明“存在解”；本协议检验玩家如何形成、否定并重组计划。本文件是样本数、评分记录与放行门槛的唯一维护处；设计原则见[高难总纲](high-difficulty/design-guide.md)，首批任务见[实验卡](high-difficulty/experiment-briefs.md)。未取得规定证据的关卡不能凭目标标签获得实测评级。

## 每次盲测

- 测试者具备所需前置知识，此前未见本关地图、内部命题或答案；已读任务书、看过回放或参与制作的人不属于该关陌生样本。
- 只允许看到游戏正常提供的胜利目标、操作和已学过的图形语言。
- 观察者不提示。图标问题先记录；必要时停止该次盲测再解释，不把接受解释后的结果混入无提示成功率。
- 因图标、遮挡、动画、输入或焦点歧义造成的失败记为关卡缺陷，不记为合理难度。
- 尽量被动观察，结束后复盘。可接受自然口述，不在关键时刻追问“是否要留路”等问题，以免采访本身给出子目标。
- 学习顺序和独立难度比较分别记录；相关候选刚刚教过的技巧不等于间隔后的自发迁移。

记录以下信息：

| 字段 | 说明 |
| --- | --- |
| 关卡 / 版本 | 目录版本、稳定 ID、显示序号、Git commit；脏工作区另记盘面指纹。E 编号在尚无地图时仅是文档编号 |
| 测试者编号 | 匿名编号，不记录不必要的个人信息 |
| 证据身份 | 作者评审 / 陌生真人 / AI；分表保存，不混合平均，不相互替代 |
| 已完成前置 / 暴露 | 所学技巧、玩过的相关候选、间隔时间；排除知识顺序不一致 |
| 第一模型与计划 | 分开记录“我认为规则怎样”和“我准备先完成什么”，不要求玩家一开始说出完整解 |
| 尝试路径 | 关键移动、回退和重开；不要求逐键转录 |
| 计划被否定的位置 | 哪个状态或可见关系否定原计划；是推理发现、操作验证还是表达歧义 |
| 新子目标与重排 | 玩家因此要先建立什么状态，如何调整先前的安排 |
| 因果里程碑 | 实际发生的领域事件与状态变化；不自动等同于玩家已经理解 |
| 最后真实顿悟 | 玩家最后一次获得使剩余计划明确的新理解，附原话与时刻；无法确认记未知 |
| 重开 / Undo 数 | 区分推理成本和执行成本 |
| 执行尾巴 | 从最后真实顿悟至胜利的有效推动、其他有效交互和行走分别记录；不能挑临近结尾事件缩短统计 |
| 会话与时间 | 活跃思考、执行、暂停、跨会话起止分开；长时间挂机不算高难证据 |
| 歧义 | 图标、盘面遮挡、动画或控制是否误导 |
| 结果与解释 | 独立解出且能解释 / 解出但解释不清 / 接受帮助后解出 / 暂停 / 放弃 |
| 难度意见 | 作者评分、测试者自评及观察记录分别保存；未知不填零，目标难度不覆盖原始意见 |

## 通用通过标准

- 建立关：至少 3 次盲测；玩家通过操作形成目标假设，不靠说明文字获得答案。
- 定界关：至少 3 次盲测；地图本身能纠正建立关后最常见的过度概括。
- 推演关：至少 5 次盲测；至少 3/5 测试者无提示发现预定二阶后果。
- 按目标难度计，D1–3 每关至少 3 名目标玩家，D4–7 至少 5 名，D8–10 至少 8 名熟悉逻辑解谜的玩家；取角色标准与难度标准中较高的样本数。
- D10 至少要有 3/8 玩家跨会话独立解出，并能用自己的话清楚解释核心洞察。
- D8–10 的实测评级必须经过作者最终确认；专家样本与作者意见分别保留，不能只用平均时长换算档位。
- 任一关出现静态不可读关键状态，直接退回候选池。
- 推演关及 D8–10 候选在最后真实顿悟之后最多 6 次有效推动；超过则退回压缩执行尾巴。理解仍在变化时，不把第一次发现叫作最后顿悟；无法确认时记未知，不视为达标。
- 评分达标不取代机器验收。预算耗尽、无效变体、状态未覆盖或宏策略枚举截断必须单列，不能当作无绕解或命题必要的证明。

## 首批 D5–6 高难实验的专门放行

适用对象：[E01–E06](high-difficulty/experiment-briefs.md)及其重构候选。[E01 原型与对照](high-difficulty/e01-prototype.md)已可试玩，其余仍只有任务书；本节是执行合同，不是已获得的人类校准结果。

1. 每张候选至少 5 名具备前置知识、未见本关地图和答案的真人测试者。作者反馈、知情测试与 AI 反馈另存，不计入这 5 名。
2. 每名记录第一计划、否定计划的关系、新子目标、计划重排、最后顿悟与执行尾巴。一次有序事件发生不等于玩家理解其作用。
3. 扩大到 D7–8 前，至少有两张作者确认为 D5、两张确认为 D6 的不同候选；同一地图的改名、镜像或不同版本不能重复计数。这四张每张至少有 3/5 陌生测试者无提示解出，并能解释它的关键资源关系；扩大样本时保持至少 60% 的比例。
4. 需同时满足地图阶段的可解、命题必要、有效解耦对照、宏策略／变异审计及静态可读性要求。对照必须解除宣称的关系，不能只让解更短。具体制作合同见[总纲](high-difficulty/design-guide.md#tool-boundaries)。
5. 作者仍评 D3–4 时，保留有价值的练习或退回实验池，改变问题结构，不提高标签。若样本多于最低人数，保留全体结果，不选择性抽取表现最好的五人凑通过。
6. 通过只放行纯空间 D7–8 生产；纯空间峰顶仍需本协议的专家与作者门槛，之后才横向制作其他机制弧。不得把文档通过、自动求解或一次作者试玩当作全部高难已成立。

首批 D5–6 同样记录最后顿悟后的推动与其他操作；若明显只是理解后搬运，即使总时间很长也不支持目标难度。角色属于推演时仍适用通用短尾硬门槛。

## Spike 概念反转专项

- 先按完整课程顺序测试 H1–H8，保留非 Spike 内容的间隔；它们主教其他技巧，Spike 仅辅助约束。机器要求是禁止两类重置仍有同成本正解、允许重置不能更短、删除 Spike 会放宽有意义的约束；比较必须使用同一明确成本目标。记录等成本重置路线是否会提前暴露工具用途，不能仅凭零重置路线存在便宣布铺垫成功。
- H8 结束后，先让测试者用自己的话解释 Spike。至少 4/5 玩家应主动避刺，并描述为“销毁／损失／回出生点恢复”，而不是计划中的远程移动工具。
- `mastery-v2` 第 70 槽至少进行 5 次盲测；至少 3/5 测试者应在无提示下重新解释同一规则，并用 origin 取得反向推侧。
- 第 71 槽按实际物件类型与已核验碰撞规则验证 origin 占用预测；不能统一宣称“任何物件占住出生区都不能回位”。在独立的揭示后边界测试中，至少 4/5 玩家能预测该类型的占用许可、完整占格和玩家留在触发侧等结果；不要用提前追问污染第 70 槽的自发发现记录。
- 记录测试者是否从静态出生点残影、接触爆炸和原位生成共同读出因果；若只能靠动画时序猜答案，关卡仍不合格。
- 在 H1–H8 尚未实现与完成顺序盲测前，实验室的三个 Spike 原型只能验证规则和表现，不能证明长期误导已经成立。
- 本专项必须由未接触揭示内容的真人完成；作者与已知答案的 AI 可检查风险，不能计入信念形成比例。角色死亡始终整盘重置，不把死亡后的跨回合进度保留作为考题。
