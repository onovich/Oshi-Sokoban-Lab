# Rain shallow-water presentation

## Status: paused, disabled in gameplay

At the author's request, Board no longer imports or mounts `WaterSurface`. Gameplay retains rain streaks and landing splashes, but has no simulated water layer or water reflections, and allocates no water-simulation GPU resources. This is a suspension, not removal of the implementation: the component, rendering modules, shared C parameters, focused tests and `/water-lab.html` remain available for future work. Do not re-enable automatically; visual acceptance is still outstanding. The implementation notes below describe the retained, inactive integration.

The water is a screen-space approximation for the flat board, not a physical fluid simulation or a new terrain rule. Clear levels do not mount it.

- `WaterSurface` owns GPU lifecycle, including unavailable WebGL and context restoration.
- `water-scene` samples the rendered glyph bounds, so reflections follow the existing CSS movement/reset animations. Reflections are vertically mirrored, compressed, and faded from the contact edge. Walls and occupied solid cells mask the water. SVG shape paints are reused rather than inventing a second icon set; numeric labels are deliberately omitted from faint reflections.
- `water-surface` samples and uploads reflection/mask textures on every browser animation frame, at up to 768 pixels wide. A previous 32 ms throttle made reflections trail the CSS animation and has been removed. The texture origin uses the board padding box, matching the overlay canvas rather than the border box. Rain landing phases use the existing CSS animation clock and landing coordinates. Rain has its own bounded queue of 32 impulses lasting 1.4 seconds.
- The author corrected the selection from B to **C / linearized shallow water**. B's pressure projection and passive optical micro-relief are no longer used by runtime. Lab C and runtime embed the same `SHALLOW_WATER_UPDATE`: 128², 1/120 s timestep, gravity .9, base depth .025, velocity damping .992, height damping .999, entrainment .22, speed clamp ±1 and height clamp ±.02. The rectangle-distance forcing Gaussian denominator is .00025. Multiple rendered glyph bases and wall bases are rasterized into a shared boundary texture; each base is bottom-anchored, with half the face height as hidden depth. Where multiple bases overlap influence, the strongest influence wins. Forcing beyond .06 normalized units is truncated (less than 0.000001 of peak); this and the multi-object rasterization differ from the analytic single-block demo.
- Contact velocity comes from consecutive CSS-rendered positions without smoothing. Large position discontinuities and long frame gaps reset momentum, avoiding board-crossing teleport wakes. This is a presentation heuristic, not an engine-event guarantee for every reset animation. Catch-up is bounded; disabled/reduced motion stops integration. Unsupported floating-point targets fall back to the existing rain/reflection surface.
- Rain landing events feed C with the lab's .00008 Gaussian and .0008 height impulse. The old analytic elliptical rain waves run only in fallback, not on top of C. Existing SVG landing splashes remain. Runtime uses C's normal gain 70, refraction offset .018, shared light directions/exponents/amplitudes, floor color (.105,.145,.15) and reflection gain .23. Screen-down Y is inverted for lab-style screen-up normals/light. The lab's reference grid and synthetic rectangle reflection are replaced by the actual board and glyph reflections; identical parameters do not mean pixel-identical scenes. The source glyphs and Goal outlines remain above water and undistorted.
- Reduced-motion preference freezes the surface and stops impulses, while state/resize updates can redraw the static reflection. Hidden documents skip rendering. Unmount cancels animation and deletes GPU resources.

Verification: Board tests cover rain-only mounting, persistence across game moves, removal in clear weather, and alignment of rain impacts with visible splashes. Browser inspection confirms the shallow reflection and changing ripples without changing the player's current board. Pixel realism, motion perception, and GPU performance still require visual acceptance on the player's device; unit tests do not establish those qualities.

Scheme C integration verification: build/typecheck and 22 contact/Board/shared-shader tests passed. Browser smoke mounted 泊庭 without shader warnings/errors. Shared-source tests guard the lab/runtime update and lighting against parameter drift, not physical accuracy. Contact tests cover half-height geometry, unsmoothed velocity and discontinuity suppression. No strict conservation, cross-device performance or fully swept moving-boundary accuracy is claimed.
