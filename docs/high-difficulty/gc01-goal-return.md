## 相对原任务书的收敛

本关属于 [GC01](goal-condition-exploration.md) 的**空间协调变体**。原任务书强调“过早清除支撑物会破坏穿过条件”；本轮小图中，这个关系往往退化成唯一入口强迫的动作顺序，不能诚实地认作新的规划。

因此保留同一机制范围，但将可证伪主张收敛为：**Goal 的最终落点和一个箱子的暂时完成，必须一起为另一箱运输及最终回程让路。** 不宣称原来的强命题已完成，也不据本关放行 GC02 或批量生产。

继承的是再借庭的“完成后还要保留取回条件”，不是相同底板；本关没有足够的外形锚点，不能当作已验证的同底板迁移。前置建议为基础 Goal 推／穿规则与一条已学会的空间回程链；开发模式不限制进入。

## 地图与角色

5×4，5 格墙；两只单格真实箱、一个单格可移动 Goal、一个静态 Goal；无其它机制。玩家可见标题为“涉岸”，不展示内部策略说明。

内部坐标零起点，b 初始 (2,2)，c 初始 (2,1)，移动 Goal g 初始 (1,2)，静态 Goal (3,2)。实体稳定 ID 以 `lab-gc01-goal-return` 为前缀。

- b 会先到静态目标附近，但不能把完成当作永久存放。其占位影响 c 的推动侧。
- g 既参与受阻穿过，又能改变 c 的最终落点。把 c 放在看似方便的西侧目标位置，会阻断最后回程。
- 北侧通路不是装饰：它提供 b 后续向下推动的站位。
- 原候选的 (1,3) 被判定为冗余，现已封墙；没有使用“可读性”标签掩盖冗余。

## 机器证据（不等同于教学或难度证据）

采用真实 `move()` 和现有 `solveLevel`，未新增或改写规则、求解器。

1. 初态有解，逐步回放每步有效，最终所有真实箱满足胜利条件。
2. 分别禁止 g 从 (0,2) 下移到 (0,3)、b 从 (3,2) 移到 (3,1)、穿过 g，均返回 `proven-unsolved`。这是各行为必要性，不宣称整个推动序列唯一。
3. 合理错误方案：把 c 完成在 (0,2)，g 也留在那里，b 已让到 (3,1)。完整搜索证实此时无法收尾；撤销最后一次推动后仍可解。因此不是对玩家说“看起来卡住就一定死局”。
4. 单变量解耦：只移除墙 (1,1)，上述错误局面变成可解；整关在禁止 g 下移的条件下也有解。被解除的是回程冲突，不只是操作数。
5. 元素删除与空格封墙审计未报告未解释冗余、无效或预算耗尽。`solution-changed` 只表示当前工具记录的解法成本变化，不等于该格对所有解都不可或缺。
6. 指定因果里程碑后的求解见证余量不超过 6 推；这不是玩家真实顿悟时刻，试玩仍需另行判断执行尾巴。
