## 1. 策划阶段决策与保护范围

本节记录策划阶段的边界，不是禁止后来制作地图。当前实施扩展为 E01、E06 及各自对照、作者追加的 E06 简化练习进入开发实验室；正式目录、旧盘面和规则继续冻结。实验室搜索只按具体证明需要补有限历史状态，不替代正式求解器或人类校准。局部可玩提示实验不等于通用提示系统放行。

- 目标体验是**规划与顿悟交织**：理解改变计划，计划又暴露新的约束；不是每关猜一次规则，也不是理解后长时间搬运。
- 保留 P1–P10 的盘面和稳定 ID，用作 D3–4 练习与对照。31–36、57–58 为作者 D3 锚点，59–60 为 D4 锚点；旧设计目标不是实测结果。[作者反馈](../playtests/2026-09-03-author-p1-p10.md)
- 保留五幕、120 个正式名额与 60 个冻结基础关。E01–E06 是文档中的实验编号，不是新增正式关号或运行时 ID，也不占用 P11／P12 的 ID。
- 策划修订阶段只更新文档；后续经作者同意继续实施，实验室现按短庭 → 旁路 → 回环重排，单列作者评级，并追加 E02 主版／对照。正式课程槽位与发布仍待校准，不改旧盘面、稳定 ID、存档格式、规则或 120 个名额。[实施记录](e02-prototype.md)
- 不引入新机制、Path Spike、限时、强制步数上限或隐藏状态。Undo 不承担解法中的“反向移动”；可恢复中间态必须能靠正常操作继续完成。
- 最初策划包没有制作地图；之后的 E01／E06／E02 原型、真实回放和作者反馈分别记录。Rain 同底板变式仍[只有设计卡](e02-rain-variant.md)，不把新构想写成已证明可解或已通过盲测。

## 3. 以资源关系为设计单位

每个候选先回答五个问题：

1. 两个任务分别需要哪片空间或哪个操作条件？为什么不能各自完成？
2. 最直观的局部成功会夺走哪项后续条件？盘面能否让玩家自己看到原因？
3. 哪个尚未完成、但可继续操作的中间状态解除冲突？
4. 资源再次被需要时，有什么条件已经变化，使前次做法不能原样照搬？
5. 解除这一个共享关系后，题目是否退化为更容易独立处理的任务？

“物件互相挡住”还不是好题。如果每一刻只有一个合理动作，或者发现一次次序便能全部执行完，仍可能只是很好的 D3–4 练习。也不能把无解的循环依赖包装成高难：所谓借路、还路必须能由真实推动和玩家可达性实现。

<a id="strategy-lines"></a>

### 六条策略主线

| 主线 | 前置技巧 | 争用资源与高阶问题 | 可迁移到哪里 |
| --- | --- | --- | --- |
| 通路借还 | 完整占格、推侧访问、暂时退步 | A 腾出的路与 A 日后仍需的推侧发生冲突；B 的中间位置决定 A 是否还能调整。 | 可移动 Goal 的通路用途；Gate 往返。 |
| 延迟收尾 | 已完成物仍可推、远先近后 | 完成位置也是流通或暂存空间；不是简单决定谁先完成，而是先制造所有任务可收尾的状态。 | 编号目标分配；Goal／Rain 的最终用途切换。 |
| 全局分配 | 完整覆盖、数字兼容、真假身份、允许空 Goal | 哪个物件最终用哪个目标，与中途借用的目标、运输路径和取回推侧相互限制。 | Fake 保留、空 Goal 调度、组合终局。 |
| 条件动作 | Goal 能推则推／受阻可穿，Rain 滑行与邻接操作 | 为一次操作制造阻挡或停止点，随后还要撤销该条件，才能完成同一物件的另一用途。 | Gate 远端条件；Goal 先作地形后作终点。 |
| 远端拓扑 | Gate 配对、方向保持、出口受阻时入口可推 | 去程和回程对端点、出口占用的要求不同；移动入口之前要准备解除远端阻挡的方法。 | Gate／Rain；揭示后的 Gate／Spike。 |
| 回位调度 | 触刺回位、按类型核对 origin 许可、玩家留在触发侧 | origin 同时是暂存或站位资源；占用帮助前一任务，却推迟下一次必要回位。 | 多格远端触发、Goal 回位、端点恢复。 |

这些是跨机制的策略弧，不替代已有机制族或新增规则。只有前置知识已经学会，才把它用于高难评价；突然遭遇未知的边界行为应先补教学或规则核验。

### 真组合的检验

- 写清 A 的选择改变 B 的哪项许可，B 的要求又怎样筛选 A 的方案。
- 给 A 一个独立资源的对照布局，观察 B 是否因此可以单独解决；反向也要说明。
- 如果移除某机制只少做一段固定动作，其他计划完全不变，标为串联练习，不标必要组合。
- 峰顶可以只用普通推箱子规则。机制多、里程碑多或解唯一，均不能代替难度证据。

<a id="technique-growth"></a>

### 两条内容扩展方向

**方向一：扩展技巧库，而不只扩写一条越来越复杂的交接链。** 从六条策略主线中寻找不同的局部方法，优先使玩家能从盘面辨认“在什么条件下，为什么要这样做”。既有推侧保留、远先近后等是前置，不因换了名字或地图就算新技巧。新候选需说明相较已有 P／E 关，新增了什么适用条件、操作用途或边界判断。

一张技巧卡应能提出这样的内部表述：**遇到某种可见约束 → 主动制造某个中间状态 → 获得一项后续能力；但在某个边界下不能直接用。** 这是给设计者检验因果的格式，不是要显示给玩家的口诀，也不要求玩家用同样措辞作答。若只能写“多试几次”或“多次改变状态”，先标为策略认识，继续寻找其中值得单独学习的局部关系。

**方向二：每当向玩家引入一个新机制，都检查旧技巧能否在它下面产生新用途。** “新”指相对于玩家的学习进度，仍限于项目已经核验的规则，不授权创造新引擎机制。先使新增规则静态可读、能被验证，再让熟悉的技巧遇到变化；不把未知规则与复杂旧技巧同时堆入第一题。

检查不要求把“每个技巧 × 每个机制”都做成地图。没有实质关系时明确记为“无新设计收益”；允许少量直接复用作巩固，但只有旧计划的适用条件、资源角色或安排方式变化时，才标为进阶。新机制不必让题目更难，也可能解除旧依赖，形成有价值的定界关。

以下是待核验的策划种子，不是直接替换某个物件就保证有解的地图：

| 已学技巧／问题关系 | 新机制条件 | 可保留的底板线索 | 需要研究的新判断 |
| --- | --- | --- | --- |
| 腾出推侧，但保留物件可恢复性 | 完整占格／不同刚性形状 | 同一个瓶颈与暂存区的位置关系 | 可容纳中心不等于容纳整块；暂存后取回侧是否仍可达，而非单纯换形状。 |
| 保留稀缺 Goal、决定空 Goal 的阶段用途 | Number | 相同目标簇与运输入口 | 几何上可用的位置是否还兼容身份，原分配与运输次序哪些必须改变。 |
| 临时占位物也需安排退出时机 | Fake | 同一条通道和借位关系 | 任务身份改变后，哪些物件不必最终归 Goal，但仍不可当垃圾随意推走。 |
| 移开阻挡以取得另一侧站位 | 可移动 Goal 的推／穿条件 | 同一窄口与前后站位 | 原来靠移走物件取得通路，现在能否通过制造受阻条件穿过；之后如何恢复另一用途。 |
| 保留取回侧、按阶段借用位置 | Rain | 同一运输走廊与侧边停靠位 | 玩家能否停在所需位置；是否必须先制造、再撤销停止物，而非照抄逐格走位。 |
| 去程前准备回程／让路后还要留路 | Gate | 两个区域及其出入口方向关系 | 本地有站位不等于远端出口可用；端点、入射方向与出口占用怎样改写往返计划。 |
| 暂时离开最终位置、用后归还空间 | Spike，正式揭示之后 | 熟悉的出生区、借位区与运输瓶颈 | 回位能否替代一段返回运输，何时应释放该类物件的 origin；不是默认所有回位许可相同。 |

这些问题进入候选任务书时仍须核对原版、作者裁定和真实规则测试。机制收益不成立就舍弃变式，不增添规则例外或多余机关来保住题材。

<a id="related-layouts"></a>

### 相似底板：让地图本身提示技巧亲缘关系

目标是让玩家产生“这里像以前那题，但有个条件不同”的感觉。保留的是足以唤起记忆的区域轮廓、目标图案、瓶颈与物件角色关系，不是强迫整张地图逐格相同。底板是一种不说答案的提示：**它暗示相关，不承诺同解。**

| 变式关系 | 什么应让玩家感到熟悉 | 什么可以改变 | 设计价值 |
| --- | --- | --- | --- |
| 巩固复用 | 同一技巧的适用线索 | 局部方向或承担任务的物件 | 加强识别；如思路不变，明确按练习计，不冒充新技巧。 |
| 条件修正／进阶 | 相同瓶颈或中间状态的用途 | 新机制使旧准备不足，或解除一个旧约束 | 保留原则，重新判断什么时候、怎样使用；也允许新解更简单。 |
| 用途反转 | 同一元素及其位置关系 | 曾经的障碍在新任务中成为资源 | 改变对用途的解释，规则与关键状态仍清楚稳定。 |
| 组合继承 | 可认出的一个或数个已学局部结构 | 另一技巧争用同一资源 | 旧技巧仍是解法组成部分，但不能各做各的；不必保留旧题全部策略。 |

每次沿用底板时，内部任务书必须回答：

1. 关联哪一题的稳定 ID／盘面版本？玩家此前实际学过哪项关系，而不只是见过图形？
2. 保留哪些可见锚点，使关联不依赖标题“进阶版”、编号或作者解释？
3. 哪个变化是可见的？它如何改变旧解法的某个具体条件？
4. 哪个原则仍然有用，哪个步骤或过度概括不能照搬？新解与旧解是继承、修正、反转还是部分组合？
5. 用真实回放、禁止条件和有效对照，如何分别检验“确有关系”与“确有变化”？
6. 若玩家没认出底板，新题是否仍能按已学规则推理，而非必须记住旧路线才能解开？

一个反例：保持地图和操作完全相同，只把一个图标换成 Gate，却从未让配对出口影响选择，这只是装饰或巩固。另一个反例：图形几乎相同、真实解法却毫无可解释的联系，仅靠即视感诱导错误；如果不能说明它定界了哪个旧判断，就不是本方向追求的变式。

熟悉锚点可以承担教学职责；不能只因它不在最短路线里就删掉，也不能以“致敬旧题”为所有冗余格开脱。说明它提示的具体关系，并通过玩家识别记录检查。优先形成少数辨识度强的底板谱系，与全新布局穿插；不把所有关卡改成同一个模板，不规定每个新机制必须生成固定数量的变式。

## 4. 难度与掌握弧

<a id="e06-accepted-arc"></a>

### 当前可用锚点与教学取舍

[作者已经认可](../playtests/2026-09-04-author-e06.md#author-acceptance)短庭 D4、旁路 D5、回环 D6，并验收该组可用。实验室现按 **短庭 → 旁路 → 回环** 学习，对应新显示号 06／07／08；历史反馈号则是 08／07／06。稳定 ID 不变，开发界面单列作者评级，旧目标 D3／D3／D5 与陌生校准另存。

实际排课时须让目录顺序、分组前置和“下一关”一起体现这条学习序列，不能只交换显示数字；仍保留稳定 ID 与原完成记录。正式玩家界面继续不显示难度数字或内部命题。

这组三题的价值包括形成“同一个块要分阶段改变状态，不能指望一步到位”的策略认识，但作者认为它尚不够直观、可归纳。**关卡质量、难度、技巧可归纳性与迁移效果是四个不同判断。** 更直观的技巧是优先选择，不是必须把所有合格复杂题压成一句口诀；静态图形／控制有歧义则仍是需要修复的缺陷，不能混为一谈。

后续教学有两条均可接受的路径，目前不强制择一或立即加关：

- 保留三题现状，按 D4 → D5 → D6 编排，承认它首先教会的是策略认识，再观察更广泛玩家的学习效果。
- 在三题之前或组内增加独立前置题，突出一项尚未被学会的交接关系；不得修改已认可盘面来降低难度或强行改变命题。新增题需在既定候选／正式名额内另行取舍，不自动把课程扩到 121 关。

如选择补教学，不能只让长物少走几步：短庭已经教了最后一段让路；回环额外需要的是“先让另一个物件离开暂存位，长物才有第二次让路的空间”，以及临时挪开的物件还要回移以释放别人的最终推侧。可从其中一个清楚可见的关系制作完整小题，但它们目前只是前置设计方向，未完成地图或证明。

E02 的作者反馈暴露了另一种教学风险：**难题达到 D6–7 的主观难度，演示功能提供后仍可能没有形成可迁移的理解。** 作者实际观看了多少步骤尚未确认，因此不能把它写成完整演示的效果结论。现已加入[窄门 → 近岸 → 再借庭](e02-return-teaching-chain.md)候选链：第一题只建立完成物让位后必须归还，第二题用单一近目标定界“归还还需要保留推侧”，第三题保持原高难盘面检验迁移。前两题已通过机器证明，尚未通过作者试玩；这里记录的是教学实验，不是新增的正式课程结论。

作者已解出 08／07、观看 06 完整演示后评级与验收；这足以记录作者裁定，但不填成三题全部独立解出、自然迁移已成功或陌生样本已齐。详细证据只在[原始记录](../playtests/2026-09-04-author-e06.md)维护。

### 体验目标，不是自动评分

| 目标档位 | 应研究的推理要求 | 不足以证明该档位的情况 |
| --- | --- | --- |
| D5 | 找到一个服务于后续任务的必要中间态，不能逐件直接完成。 | 原有“一次让路后复原”换一个朝向。 |
| D6 | 同一资源再次交接时条件改变，需要调整已有计划。 | 把同一次开门重复两遍。 |
| D7 | 两条已学策略互相限制，必须协调而非拼接。 | 左边推箱，右边单独用 Gate。 |
| D8 | 根据最终占格或远端条件，筛掉多个局部看来成立的计划。 | 仅增加分支数或最短路长度。 |
| D9 | 提前准备多次资源交接，避免局部正确却无法恢复的布置。 | 让错误很晚才被不透明动画揭示。 |
| D10 | 建立解释整张地图的资源关系，并据此组织多阶段计划；以专家可能跨会话解决为目标。 | 扩大地图、强迫记更多状态或延长机械搬运。 |

同一种结构对熟练者可能很容易。以上描述只能决定制作假设，不能事先宣布评分；真实锚点和放行按[试玩协议](../playtest-protocol.md#high-difficulty-pilot)处理。D1–2 不由本轮补造，不能把已评 D3 的旧题改名为 D1 来补齐曲线。

### 掌握过程与迁移

识别关系 → 变式运用 → 遇到适用边界 → 协调其他要求 → 间隔后重新使用 → 高难综合。

| 阶段 | 设计任务 | 玩家理解的证据 |
| --- | --- | --- |
| 识别 | 可在完整谜题中主动使用技巧，而不是按唯一按钮。 | 能解释动作解决了什么局部问题。 |
| 变式 | 改变关系的承担者或空间组织。 | 无标题提示仍能认出可用关系。 |
| 定界 | 让原本正确的方法在一个可见条件下失效。 | 能说出适用条件，不是猜新例外。 |
| 协调 | 使用技巧会消耗另一任务的条件。 | 先安排中间态再取得局部成果。 |
| 回访 | 插入其他课程后，再使用熟悉底板或不同外观的相关问题。 | 自发调用关系，能辨认条件变化，而非机械重放旧路线。 |
| 综合 | 已学策略共同约束同一资源。 | 解释为什么不能分别解决再拼接。 |

学习顺序与测量顺序分开。课程需要铺垫和回访；实验比较则须记录测试者见过哪些相关候选，避免把相邻关给出的提示当作单关自然可读性。

实际教学可先用强底板相似性帮助提取旧技巧，再逐步减弱表面相似，或将其嵌入新机制／组合题。新机制的入口既要有规则建立，也要回顾哪些旧技巧值得带进来；两者可以由同一完整小题承担，但不能让玩家同时猜多个未知量。相邻熟悉题之间也需有真实问题变化，间隔回访则防止整段课程退化成短期动作记忆。观察方式统一见[迁移取证](../playtest-protocol.md#technique-transfer-evidence)。

<a id="production-sequence"></a>

### 后续生产顺序

1. 保留已验收的 E06 三题与新的 D4–6 作者锚点。并行策划两类问题：现有组是否值得补一张更清晰的前置题；还能从 [E02–E05 或新候选](experiment-briefs.md) 提炼哪些不同技巧。纯空间 D5–6 的下一原型优先验证一个较清楚、可归纳的关系，不只延长 E06 交接链；广泛生产放行仍按试玩协议。
2. 再研究纯空间 D7–8：用已成立的借还与延迟收尾关系，迫使玩家协调而非简单重复。
3. 再做纯空间峰顶候选，经作者与专家验收后，才能放行横向地图生产。这替代“等待旧 P1–P10 自动变成高难”的阻塞条件，不重写旧 ID。
4. 依次迁移至目标分配、Goal／Rain、Gate、Spike；每条策略弧先通过机器审计与相应试玩再展开下一条。每次机制教学的策划都立即检查[旧技巧迁移](#technique-growth)，不必等峰顶通过才思考，但跨机制高难地图的批量生产门槛不因此提前放行。
5. 最后筛选必要的二至三机制综合及远端拓扑峰顶，按实测结果讨论正式收录。不得因预留的 D9／D10 名额尚空而降低门槛。

生产顺序不等于课程显示顺序。H 关可以后制作、再按已定五幕蓝图置于揭示之前；本次只整合实验室的 E06 学习顺序，正式课程不变。

## 5. Spike 与 Goal 的长期认知线

<a id="spike-belief-design"></a>

### Spike：先有实际损失，再有用途反转

H1–H8 仍分散于第 70 槽之前，正式回位揭示仍占第 70–75 槽。不向冻结盘面添加 Spike，不让标题点名“传送技巧”。下表是桥接设计意图，不是已完成地图：

| 桥接 | 主要技巧 | Spike 作为辅助约束的作用 |
| --- | --- | --- |
| H1 | 推侧选择 | 直推路线看似接近目标，触刺却丢失有用位置。 |
| H2 | 完整占格 | 远端组成格的触刺风险排除只看锚点的走法。 |
| H3 | 目标分配 | 最近兼容目标的直接路线被排除，仍需按主技巧分配。 |
| H4 | 可移动 Goal 的暂存 | 一个诱人的暂存位置导致有用 Goal 布置被重置。 |
| H5 | Rain 停点 | 直滑途中触刺失去进展，必须先安排安全停止位置。 |
| H6 | Gate 入射方向 | 错误方向使出口行程触刺，主要问题仍是方向与落点。 |
| H7 | Fake 的资源用途 | 将 Fake 当垃圾清走会撤销有用布置，必须保留它的作用。 |
| H8 | 已学技巧综合 | 重要布置之后，触刺有实际代价；不是增加一颗无关装饰刺。 |

每次触刺都遵守同一真实行为。允许玩家观察销毁与出生点重生；需要自然形成的是“在这里，碰刺会丢失进展”的有效策略，不是假规则“永远消失”。桥接之间保留非 Spike 课程作为间隔。

桥接的成本比较、重置禁用、删除变异及信念比例统一按[Spike 专项验收](../playtest-protocol.md#spike-belief)执行，不在这里再维护一份合同。设计上要区分“存在一条避刺路线”与“玩家有理由持续避刺”；哪些动作造成真实损失、哪些路线可能提前暴露工具用途，都要留回放证据。

揭示关反过来让物件回位不可绕过：旧的“永远避刺”策略不足以取得所需推侧，但回位后玩家仍在触发侧。之后迁移到 origin 的暂存／站位用途、释放时机和远端组成格触发。已经知道真相的作者可以评估策略深度，不能代替新玩家评价误导是否自然。

同底板可串联“此前应避开的路线”与“揭示后可借回位获得的推侧”，但第 70 槽之前不能为了展示跨机制技巧，提前把必要回位当作正解教授。H 关仍以原主技巧和真实损失为中心；揭示后的变式再利用熟悉结构表达用途反转。不得通过隐藏 origin 或变更规则维持误导。

### 回位许可不是统一的“必须空无一物”

当前规则核对入口为[规则引擎](../../src/engine/game-engine.ts)及[领域事件测试](../../src/engine/domain-events.test.ts)。策划任何依赖回位的变式前，分别核对：

- Block／Fake 的回位会受角色、其他 Block、Gate 和墙等阻挡；Goal 层不等于实体阻挡。
- Gate 的实体回位许可与角色通过配对出口的许可分开，不能借用同一描述。
- Goal 的回位许可也不同于普通推动；当前 `canResetGoal` 不以 Block 作为阻挡条件。需要专门边界用例支持后才能把该差异当作高难解法，不能因一条宽泛的 origin 描述擅自改规则。
- 角色触刺走独立整盘重置，不设计“死亡后保存先前成果”的技巧。

以上是核查入口与使用限制，不是本轮追加或裁定新规则。未完成来源、测试与可读性核验的边界留在候选池。

### Goal：从定界知识变成反复使用的资源

“Goal 可以多余”和“玩家不参与胜利”在基础阶段划定规则边界。掌握阶段改问：最终该留空哪一个、谁能临时借用它、何时需要腾出它对应的站位？E03 在静态 Goal 中研究这些关系；后续再迁移到可移动 Goal 与 Rain。

不要反复假定熟悉玩家还相信“玩家也要进 Goal”。旧误解只作为新玩家可能出现的模型记录，不能靠文案硬塞给玩家。已全箱完成之后也不能追加返程目标来照搬 SSR 的结构。

## 6. 后续地图的制作合同

### 任务书先于坐标

每张实验卡必须有：前置、总命题、资源冲突、自然第一计划、地图反证、必要中间态、因果里程碑、收尾条件、元素职责、禁止条件、解耦对照、绕解风险、试玩问题及淘汰标准。另标明它主教可归纳技巧、策略认识还是已有技巧的协调；新增机制时记录旧技巧迁移检查，同底板变式记录亲缘锚点与因果变化。共用字段见[任务书增补](experiment-briefs.md#teaching-and-lineage-contract)，不在玩家界面展示。

里程碑描述“哪个后续条件因此成立”，不能只列 A 推一下、B 推一下。任务书不预填假的坐标、路线、最短步数或通过记录；地图阶段再将语义条件绑定到实际盘面。

### TDD 与证据顺序

1. 在真实 `move()` 边界先固定所需规则与失败情境，再制作最小完整地图。已有测试能覆盖的规则不复制另一套实现。
2. 求解、回放；查初态不是已胜利，也不是纯按键演示。后续所有真实 Block 的最终覆盖仍是唯一任务目标。
3. 禁止某项核心策略条件，证明不存在绕过它的解。最终完成动作、因物件存在而必然出现的任意推动，不单独充当深层命题的证据。
4. 解耦对照只改变指定资源关系；如果只能做到一组几何改动，要列明它们服务的同一个因果变量，不能冒充只改了一格。对照应解除目标规划要求，而不是仅缩短走路。
   对同底板变式另核对继承关系：分别回放新旧图，检验旧方法在哪个可见条件下仍有用、失效或变得不再必要。不能要求每个教学变式都逐格相同，也不能把多处设计变化伪装成严格的单变量实验。
5. 枚举适当成本窗口的宏策略、检查必要性和变异。等价走位不算另一策略；成本窗口与枚举截断都须记录。
6. 做静态读盘与实际交互核验，包括 Undo／Restart、动画过程、首次和最后理解时刻。清晰的复杂关系可以保留，操作或图形歧义必须修复。

可读性压缩不是盲目删格。元素可承担证明、合理错误方案、对照表达或静态可读性；必须说明其职责。没有这些用途才判为冗余，不能只因最短步数不变就删除。

<a id="tool-boundaries"></a>

### 现有工具能说明什么

| 入口／指标 | 当前实际含义 | 策划使用边界 |
| --- | --- | --- |
| `interactionDepth` | 最佳计划中非行走动作数 | 不是人类推理层数，不能直接给 D 评分。 |
| `firstIrreversibleAction` | 当前记录首个推动或回位动作 | 不证明该动作不可逆；需单独核验是否仍存在恢复路径。 |
| `meaningfulBranchPoints` | 搜索中有多个后继的节点计数 | 不等于玩家眼中有意义的决策数。 |
| 证明条件 | 当前支持事件、计数、有序事件序列 | 对可达区域、可恢复性等语义条件，先明确缺口；不能声称事件出现就完整证明策略。 |
| 宏策略与变异报告 | 受成本窗口、计划截断和预算影响 | 未完整覆盖时不宣布唯一；删除导致无效输入也不等于证明关键。 |

定义见[求解器](../../src/solver/level-solver.ts)、[作者分析](../../src/solver/author-analysis.ts)和[变异审计](../../src/levels/level-mutation-audit.ts)。本轮不更名、不新增指标、不扩建求解器；把不足作为后续工具任务记录。E02 用测试侧真实行走／推动核验具体暂存状态的取回许可，不将其冒充一般策略证明器。任何预算耗尽、无效变体和未覆盖情况均保留为未知；人工看过一条路线也不能填成穷尽证明。
