# 关卡验收记录

2026-09-29。验收与通关、难度评分、机器可解、冻结保护是不同数据。

唯一记录入口：`src/course/level-acceptance.ts`。每条记录含稳定 ID、规范化盘面/命题指纹、评审身份、结论和证据文件。显示顺序和纯文案变化不使验收失效；盘面或命题变更后，旧版本记录保留，但显示待重新验收。

| 显示 | 含义 |
| --- | --- |
| 待验收 | 没有当前版本的明确结论；机器通过或试玩报告本身不自动授予验收 |
| AI 初审通过 · 待作者验收 | 陌生 AI 操作与解释、设计复核支持保留；只是中间状态 |
| AI 初审待改进 | AI 初筛发现需处理的问题，不代表作者否决 |
| 作者验收通过 · 最终 | 作者明确认可；优先于 AI 意见 |
| 作者退回 · 待改进 | 作者不认可；即使以后 AI 通过，也不能覆盖 |
| 盘面已变更 · 待重新验收 | 有历史验收，但不是当前版本 |

同一版本优先选最新作者结论，没有作者结论才选最新 AI 结论。作者改变结论时追加，不抹去历史。新版本不能继承旧版本的通过；不以保存游戏的“已完成”状态自动写入验收。

首批迁入有明确证据的 60 基础关、三条获认可教学链和转岸/涉岸。单有评分、通关、冻结保护或“很精妙但没学会”的历史反馈，不自动扩张为最终验收。其余保留待验收，可依据作者后续明确结论追加；这不撤销原始评价。

验收显示在开发页当前关卡与课程地图。正式玩家页和独立盲测页不显示。盲测入口：`/playtest.html?level=<稳定ID>`，隔离在 sessionStorage；隐藏作者工具、内部章节/阶段、选关及演示。无参数的既有试玩课程入口仍保留。

## 本批提交纪律

先保存推送既有工作；此后每完成一关，完成针对性验证与仓库配置的全套检查，将地图、测试、审计、证据和验收结论一起提交推送。最后检查 `git status` 为空、HEAD 与 upstream 一致。失败时修复并重跑，不以跳过检查或强推制造干净状态。AI 评审若未通过，关卡可以作为待改进候选保存，不能计入已验收批次名额。

探索脚本产生的候选不算完成一关；不得因此打断作者验收。继续以整批章节为作者交付单位。
