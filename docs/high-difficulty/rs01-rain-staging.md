## 问题、来源与范围修正

从 [E02 Rain 卡](e02-rain-variant.md) 的“暂存同时影响雨中推侧”问题出发。固定原地图目标和墙体、改变两个多格物起点的 154 个有效配置只找到 5 个有解配置，没有符合本轮结构筛选的候选。随后重新安排目标、起点和墙体，加入一个有真实完成任务的单格物；不是给折返庭仅换天气，也不声称维持强烈同底板亲缘。

可复现来源是 `node scripts/audit-rain-staging.mjs`，确定种子 20260909，三物件轮次第 4311 个生成尝试。该轮实际搜索 3321 个合法配置，7 个有解、1 个预算耗尽；预算耗尽保持未知。动作数只用于减少人工分析候选的范围，不是难度评分。筛选后人工核对关系、反事实与压缩；初稿左下 (0,4) 无用途，改成墙。脚本保留初稿来源，发布候选以源码和测试为准。

采用两个不可旋转双格物＋一个单格物，五个静态目标。没有可移动 Goal、Gate、Spike、数字或新规则。

## 唯一总命题与具体关系

**横物必须先深暂存再取回，单格物的位置与横物后续运输共同约束雨中推侧。**

竖物 A 初始 (3,2)，横物 B 初始 (1,1)，单格物 C 初始 (3,1)。坐标零起点。

- 横物先下放至 (1,3)，才能取得右侧竖物的操作位置；之后必须再取回到 (1,2)，不能把“下放让路”当成永久布置。
- 单格物初期在上排提供停点。竖物在右上完成后仍是停止边界，因此局部完成本身也改变其余任务的接近方式。
- 单格物移到下部后又阻挡横物收尾，必须绕运它，不能简单让所有物件朝最近目标走。
- 单格物任务不能删除后照样声称协调成立；删除审计会产生绕解，三个物件均有证明用途。

这是“物件位置决定他物运输”的候选，不把它冒称为原 E02 卡中同一刹车撤除后反复重建的全部设想。其教学迁移效果尚无证据。

## 机器证据

测试边界沿用真实 `createGame`／`move`、`solveLevel`、变异审计及 App 交互。不修改引擎或另造模拟规则。

- 当前见证 50 次有效移动、16 推，逐步回放获胜。
- 分别禁止 B (1,2)→(1,3)、B (1,3)→(1,2)、C (3,3)→(2,3)，三个完整搜索均为 `proven-unsolved`。这些不是必然发生的最后覆盖一步。
- 仅改晴天，分别禁止同样条件仍有解，见证可回放。支持这些调整与 Rain 的关系，但不等同于证明每个玩家都能理解关系。
- 可达前缀之后，C 阻挡让玩家从 (0,1) 向右停在 (2,1)；局部移除 C 后停在 (3,1)。后者是行为因果干预，不冒称是合法走出的另一局面或整关解耦。
- 物件删除、目标删除和可封空地审计没有未说明冗余、无效或未知项。此前多出的 (0,4) 已封墙。
- 最优 +2 推／+8 移动窗口返回 3 条路线、3 个推动策略签名，窗口搜索完成。不宣称策略唯一；这不是 D8–10 峰顶认证。
- C 首次从 (3,3) 左移为因果里程碑，所选见证余下 5 推。它不是实测顿悟时点，也不能据此声称顿悟之后没有新的规划。
- 机器审计上限 80,000 状态。入口：`npx vitest run src/levels/lab/rs01-rain-staging.test.ts src/App.rain-staging.test.tsx`；详细诊断：`node scripts/audit-rs01.mjs`。
