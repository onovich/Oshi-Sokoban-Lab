# Rain shallow-water presentation

The water is a screen-space approximation for the flat board, not a physical fluid simulation or a new terrain rule. Clear levels do not mount it.

- `WaterSurface` owns GPU lifecycle, including unavailable WebGL and context restoration.
- `water-scene` samples the rendered glyph bounds, so reflections follow the existing CSS movement/reset animations. Reflections are vertically mirrored, compressed, and faded from the contact edge. Walls and occupied solid cells mask the water. SVG shape paints are reused rather than inventing a second icon set; numeric labels are deliberately omitted from faint reflections.
- `water-surface` samples and uploads reflection/mask textures on every browser animation frame, at up to 768 pixels wide. A previous 32 ms throttle made reflections trail the CSS animation and has been removed. The texture origin uses the board padding box, matching the overlay canvas rather than the border box. Rain landing phases use the existing CSS animation clock and landing coordinates. Rain has its own bounded queue of 32 impulses lasting 1.4 seconds.
- Earlier prescribed movement rings/shear/streaks were rejected and remain removed. At the author's subsequent request, scheme B now drives interaction: `water-flow` evolves a 128² horizontal velocity field with semi-Lagrangian transport and 24 pressure-projection iterations per fixed 1/120 s step. A passive micro-relief scalar is advected by that field and perturbs reflection normals. It is optical detail, not simulated water elevation. Multiple rendered glyph bases and wall bases are rasterized into a shared boundary texture; each base is bottom-anchored, with half the face height as hidden depth.
- Contact velocity comes from consecutive CSS-rendered positions without smoothing. Large position discontinuities and long frame gaps reset momentum, avoiding board-crossing teleport wakes. This is a presentation heuristic, not an engine-event guarantee for every reset animation. Catch-up is bounded; disabled/reduced motion stops integration. Unsupported floating-point targets fall back to the existing rain/reflection surface.
- `water-shaders` retains expanding 10:3 elliptical waves only for rain, matching the SVG splash. The source glyphs and Goal outlines remain above it and undistorted. The separate lab still compares A/C; scheme B's historic experiment is described in `research/interactive-water-study.md`.
- Reduced-motion preference freezes the surface and stops impulses, while state/resize updates can redraw the static reflection. Hidden documents skip rendering. Unmount cancels animation and deletes GPU resources.

Verification: Board tests cover rain-only mounting, persistence across game moves, removal in clear weather, and alignment of rain impacts with visible splashes. Browser inspection confirms the shallow reflection and changing ripples without changing the player's current board. Pixel realism, motion perception, and GPU performance still require visual acceptance on the player's device; unit tests do not establish those qualities.

Scheme B integration verification: build/typecheck and 20 contact/Board tests passed. Browser smoke mounted a rain level without shader warnings/errors and exercised a rightward slide. Contact tests cover half-height geometry, unsmoothed velocity and discontinuity suppression. No strict incompressibility, conservation, cross-device performance or fully swept moving-boundary accuracy is claimed.
